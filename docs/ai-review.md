# AI-ревью модуля `billing.py`

Инструмент: Claude Code (модель Claude Sonnet). Ревьюился «черновой» вариант после первого исправления (коммит «Исправлено: округление минут вверх целочисленно…»):

```python
def calculate_cost(duration_seconds):
    if duration_seconds < 0:
        raise ValueError("duration_seconds must be >= 0")
    minutes = -(-duration_seconds // 60)  # округление вверх без float
    return 50 + minutes * 8
```

## Где ИИ ошибся при генерации (до ревью)

Первый черновик (`round(duration_seconds / 60)`) **не проходил 4 теста из 7**:

1. `round()` округляет к ближайшему, а не вверх: 17 мин 10 с → 17 мин (186 ₽ вместо 194 ₽); 1 с → 0 мин (50 ₽ вместо 58 ₽).
2. Для `.5` Python использует банковское округление: `round(0.5) == 0`, `round(2.5) == 2` — отдельная ловушка.
3. Не было проверки отрицательной длительности.

Тесты были написаны по постановке (не «под код»), поэтому поймали ошибку сразу; исправление — целочисленное округление вверх, затем `Fraction` + `math.ceil`.

## Результат после правок

- 30 тестов, покрытие `billing.py` — 100 %.
- Публичное поведение для базовых сценариев постановки не изменилось (`0 → 50`, `17:10 → 194`, `6 ч → 2930`), изменился тип результата: `int` → `Decimal`.
